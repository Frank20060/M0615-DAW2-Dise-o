## 2. 📊 Evaluación WCAG 2.1 (Nivel AA)

### 👁️ Perceptible

* **1.1.1 Contenido no textual (A)**
  * **Estado:** ✅ Cumple
  * **Explicación:** Las imágenes informativas tienen texto alternativo (`alt`) descriptivo y correcto. Las imágenes decorativas (iconos, flechas) implementan `alt=""` combinado con `aria-hidden="true"`, ocultándolas correctamente para los lectores de pantalla.
  
* **1.4.3 Contraste (Mínimo) (AA)**
  * **Estado:** ⚠️ Parcial / Sin revisar
  * **Explicación:** Se aplican clases de color de Bootstrap (`bg-primary`, `text-white`), pero es necesario asegurar mediante pruebas que la combinación con los colores definidos en CSS cumple el ratio de 4.5:1 para texto normal y 3:1 para texto grande.
  * **Recomendación:** Verificar los colores con una herramienta de contraste (ej. WebAIM Contrast Checker).

### ⌨️ Operable

* **2.1.1 Teclado (A)**
  * **Estado:** ✅ Cumple
  * **Explicación:** Todos los elementos interactivos (`<button>`, `<a>`, `<input>`) son nativos de HTML, asegurando su operatividad por teclado por defecto.

* **2.4.1 Evitar bloques (A)**
  * **Estado:** ❌ No cumple
  * **Explicación:** Los usuarios que navegan por teclado deben tabular por todos los enlaces de navegación de la cabecera antes de poder acceder al contenido principal en cada página.
  * **Ejemplo concreto:** No existe ningún enlace ancla inicial para saltar la navegación.
  * **Recomendación específica:** Implementar un enlace al principio del `<body>` que solo sea visible al recibir el foco: `<a href="#home" class="visually-hidden-focusable">Skip to main content</a>`.

* **2.4.2 Páginas tituladas (A)**
  * **Estado:** ⚠️ Parcial
  * **Explicación:** La página define un título genérico `<title>Fitness Online</title>` en el HTML, usando JavaScript para inyectar la sección actual después de la carga. Si bien funciona dinámicamente, sería ideal contar con un fallback completo en el HTML estático.

* **2.4.7 Foco visible (AA)**
  * **Estado:** ⚠️ Sin revisar
  * **Explicación:** Depende enteramente de los estilos CSS (`:focus` / `:focus-visible`). Se asume el comportamiento base de Bootstrap, pero debe validarse navegando físicamente con la tecla `Tab`.

### 🧠 Comprensible

* **3.1.1 Idioma de la página (A)**
  * **Estado:** ✅ Cumple
  * **Explicación:** La etiqueta `<html>` incluye `lang="en"`.

* **3.3.1 Identificación de errores (A)**
  * **Estado:** ✅ Cumple
  * **Explicación:** El formulario utiliza los atributos nativos de HTML5 (`required`) y atributos ARIA complementarios (`aria-required="true"`) facilitando la prevención de envíos vacíos.

### 🧩 Robusto

* **4.1.2 Nombre, función, valor (A)**
  * **Estado:** ✅ Cumple
  * **Explicación:** Todos los campos de formulario tienen su respectivo `<label>` asociado mediante `for="..."` al `id="..."` del input. Los acordeones (FAQ) cuentan con botones accesibles generados y controlados mediante los atributos `data-bs-*` de Bootstrap, lo cual es semánticamente sólido.

## 3. 🚨 Análisis del Informe TAW

El informe automático de TAW detectó diversas posibles incidencias, muchas de las cuales son revisiones manuales o **falsos positivos** frente a implementaciones ARIA modernas:

* **1.1.1 - Imágenes con alt vacio (Desconocido / Error manual)**
  * *Explicación TAW:* Alerta sobre la presencia de atributos `alt=""` vacíos.
  * *Realidad:* **Falso positivo**. En el código fuente actual, estos elementos acompañan a un `aria-hidden="true"` (p.e. `Líneas 266, 285`). Es la práctica correcta en WCAG para excluir contenido puramente decorativo.
  * *Acción:* Ninguna, el desarrollador lo ha implementado de forma impecable.

* **1.4.3 - Contraste (Sin revisar)**
  * *Explicación TAW:* La herramienta no es capaz de procesar contrastes por superposición de fondos CSS complejos o clases dinámicas.
  * *Realidad:* **Problema potencial real**.
  * *Acción:* El desarrollador debe comprobar las métricas de color reales, en especial sobre la sección "Pricing" donde conviven colores de fondo (ej: `#9765d7`) y de texto.

* **2.4.2 - Páginas tituladas (Desconocido)**
  * *Explicación TAW:* Pide confirmar que el texto dentro de `<title>` sea suficientemente descriptivo.
  * *Realidad:* Aunque es válido, el documento inicial carga como "Fitness Online" a secas.
  * *Acción:* Modificar la etiqueta estática inicial a `<title>Fitness Online - Home</title>` para dotarlo de más especificidad.

* **3.3.1 a 3.3.4 - Identificación y prevención de errores (Desconocido)**
  * *Explicación TAW:* Requiere verificar si los errores en el formulario son identificables de forma clara para usuarios con discapacidades cognitivas o invidentes.
  * *Realidad:* El uso actual de HTML5 `required` provee la solución nativa mínima. No hay "errores de TAW", solo requiere comprobación manual.

## 4. 🛠️ Mejoras Recomendadas

### 🔴 Críticas (bloquean cumplimiento AA)
*Ninguna que detenga la usabilidad crítica, pero existen barreras notables para navegación específica:*

### 🟠 Importantes (afectan UX/accesibilidad)
* **Problema:** No existe vía directa para omitir la barra de navegación repetitiva (2.4.1).
* **Impacto:** Fatiga y barrera de acceso severa para navegantes de teclado y lectores de pantalla.
* **Solución concreta:** Añadir un enlace de "salto al contenido" utilizando la clase nativa de bootstrap inmediatamente después de abrir el `<body>`:
  ```html
  <body>
    <a href="#home" class="visually-hidden-focusable">Skip to main content</a>
    <!-- resto de la página -->
  ```

### 🟢 Mejores prácticas
* **Problema:** `<title>` base genérico.
* **Impacto:** Pequeño, optimización en carga inicial.
* **Solución concreta:** Actualizar la etiqueta `<title>`:
  ```html
  <title>Fitness Online - Home</title>
  ```
* **Problema:** Revisión de contraste manual requerida.
* **Impacto:** Crucial para personas con baja visión.
* **Solución concreta:** Emplear una extensión de navegador (Axe DevTools o WAVE) para confirmar la legibilidad de colores.
