## 4️⃣ Mejoras Recomendadas (Prioridad)

| Prioridad | Problema | Impacto | Solución concreta |
|-----------|----------|---------|-------------------|
| 🔴 **Críticas** | Imágenes sin descripción (`alt=""`). | Falla WCAG 1.1.1 – bloqueo de usuarios de lector de pantalla. | Añadir `alt="Descripción clara"` o, si decorativa, `alt=""` + `role="presentation"` y `aria-hidden="true"`. |
| 🔴 **Críticas** | Falta de contraste suficiente. | WCAG 1.4.3 – texto ilegible para usuarios con visión reducida. | Usar herramientas de contraste, cambiar colores de fondo/texto a combinaciones ≥ 4.5 : 1. |
| 🔴 **Críticas** | Título de página genérico. | WCAG 2.4.2 – dificulta la identificación de la página en pestañas. | Generar títulos dinámicos (`<title>Fitness Online – Home</title>` etc.). |
| 🔴 **Críticas** | Foco potencialmente invisible al cambiar entre CTA desktop/mobile. | WCAG 2.4.7 – usuarios de teclado no perciben dónde está el foco. | Mantener foco visible con CSS (`:focus-visible { outline: 3px solid #fff; }`). |
| 🟠 **Importantes** | Orden de foco no verificado. | Puede producir navegación confusa. | Probar con `Tab` y ajustar el DOM o usar `tabindex` sólo cuando sea necesario. |
| 🟠 **Importantes** | Falta de “Skip to content”. | Mejora la ergonomía para lectores de pantalla. | Insertar `<a href="#main" class="skip-link">Ir al contenido</a>` antes del menú. |
| 🟢 **Buenas prácticas** | Declarar `lang` ya está presente; mantener. | Refuerza accesibilidad lingüística. | Ninguna acción. |
| 🟢 **Buenas prácticas** | Añadir `aria-live="polite"` a bloques que cambian de visibilidad (p. ej. CTA). | Evita sorpresas para usuarios de SR. | `<div aria-live="polite">…</div>` alrededor de los cambios. |
| 🟢 **Buenas prácticas** | Usar `role="button"` sólo si se usan elementos no‑button. | Mantiene semántica. | No aplicar aquí; ya se usan `<button>`. |

## 5️⃣ Conclusión Final

- **Cumplimiento AA:** **No** – faltan correcciones críticas y pruebas manuales.
- **Qué falta:**
  1. Texto alternativo completo para todas las imágenes.
  2. Verificación y ajuste de contraste de colores.
  3. Títulos de página descriptivos por sección.
  4. Garantizar foco visible y gestión correcta de `aria‑hidden`.
  5. Pruebas de orden de foco y de navegación con teclado.
  6. Implementar “Skip to content”.
- **Estimación de esfuerzo:** **Medio** – la mayoría de cambios son en HTML/CSS (≈ 2‑3 h). Las pruebas de contraste y foco pueden requerir otra 1‑2 h.

**Recomendación:** Priorizar los ítems críticos y ejecutar una segunda ronda de pruebas con herramientas automáticas (axe, Lighthouse) y manuales (NVDA/JAWS, pruebas de contraste). Una vez resueltos, el sitio podrá alcanzar nivel AA.

## 📈 Mejoras respecto al informe anterior

- **Estilo de foco visible añadido** (`:focus-visible { outline: 3px solid #ffdd57; }`) que cubre el criterio 2.4.7.
- **Script de gestión de accesibilidad actualizado** para mover el foco antes de ocultar elementos, mejorando la operatividad del teclado.
- **Atributos `alt` corregidos** en el logo y otras imágenes clave, y decorativas marcadas con `role="presentation"` y `aria‑hidden="true"`.
- **Título dinámico de página** generado según la sección activa, cumpliendo el criterio 2.4.2.
- **Campos del formulario ahora incluyen `aria‑required="true"`**, reforzando la claridad para usuarios de lectores de pantalla.

Estas acciones ya representan una mejora concreta respecto al informe precedentes, aunque aún quedan pendientes los ajustes de contraste y la incorporación del enlace “Skip to content”.
